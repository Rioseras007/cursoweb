Enunciado (Descripción)

A la hora de publicar nuestra página web debemos optar por un servidor web. En este servidor web encontraremos una serie de carpetas donde en alguna de ellas alojaremos nuestras páginas web. Esta carpeta tiene permisos bien diferenciados del resto de carpetas o directorios.

Para realizar este ejercicio puedes utilizar un servicio de alojamiento gratuito tipo https://www.000webhost.com/ o bien utilizar un servicio de alojamiento al que dispongamos de acceso ftp y con un cliente ftp revisar los permisos.

Preguntas y actividades a realizar

1

¿Qué permiso tienen las carpetas del servidor?

En los servidores web basados en Linux, la correcta configuración de los permisos de archivos y directorios constituye un aspecto fundamental para garantizar tanto el funcionamiento del servicio como la seguridad del sistema.

Los directorios que alojan sitios web suelen configurarse con permisos 755 (drwxr-xr-x), lo que permite al propietario leer, escribir y acceder a su contenido, mientras que el grupo y el resto de usuarios únicamente disponen de permisos de lectura y acceso.

Esta configuración facilita que el servidor web pueda recorrer la estructura de directorios y servir el contenido a los clientes sin otorgar permisos de escritura innecesarios.

Es importante destacar que, en el caso de los directorios, el permiso de ejecución (x) no implica la ejecución de programas, sino la posibilidad de acceder o atravesar el directorio. Este permiso resulta imprescindible para que el servidor web pueda localizar los archivos que componen el sitio, como documentos HTML, hojas de estilo CSS, scripts JavaScript o aplicaciones PHP. Sin él, el acceso al contenido quedaría bloqueado, incluso aunque los archivos dispusieran de permisos de lectura.

Como práctica recomendada, los directorios se configuran habitualmente con permisos 755, mientras que los archivos utilizan permisos 644 (-rw-r--r--), permitiendo que únicamente el propietario pueda modificarlos. Esta combinación sigue el principio de mínimo privilegio, reduciendo el riesgo de modificaciones no autorizadas y contribuyendo a mantener la integridad, disponibilidad y seguridad de la aplicación web. Por ello, la correcta gestión de los permisos constituye una medida esencial dentro de la administración y protección de cualquier servidor web moderno.

¿Tienen diferentes permisos?

Naturalmente sí, el usuario no debe poder eliminar o modificar ciertos archivos.

2

¿Qué permisos son los que diferencian un directorio público de otro no público?

La diferencia entre un directorio público y uno no público en un servidor web radica principalmente en los permisos de acceso asignados a los usuarios y al propio servidor web. Un directorio público está configurado para que el servidor pueda acceder a él y servir su contenido a los clientes, mientras que un directorio no público restringe dicho acceso para proteger información sensible o archivos de configuración.

Directorio Público

En la mayoría de los servidores Linux, un directorio público suele tener permisos 755 (drwxr-xr-x), lo que permite que el propietario lea, escriba y acceda al directorio, mientras que el grupo y el resto de usuarios pueden leer y acceder a su contenido. Esta configuración es suficiente para que el servidor web pueda recorrer la estructura de directorios y entregar los archivos solicitados por los usuarios.

Directorio No Público

Por el contrario, un directorio no público emplea permisos más restrictivos, como 750 (drwxr-x---) o 700 (drwx------). Con permisos 750, únicamente el propietario y los miembros del grupo autorizado pueden acceder al directorio, mientras que el resto de usuarios no tiene ningún tipo de acceso. Con permisos 700, el acceso queda reservado exclusivamente al propietario.

Estas configuraciones se utilizan para proteger archivos confidenciales, copias de seguridad, registros del sistema, credenciales o cualquier información que no deba ser accesible desde la web.

En consecuencia, el permiso que marca la diferencia entre un directorio público y uno privado es la existencia o ausencia de permisos de lectura (r) y ejecución (x) para el grupo y otros usuarios.

Mientras que un directorio público concede estos permisos para permitir el acceso al contenido, un directorio no público los restringe con el fin de preservar la confidencialidad y aumentar la seguridad del servidor.

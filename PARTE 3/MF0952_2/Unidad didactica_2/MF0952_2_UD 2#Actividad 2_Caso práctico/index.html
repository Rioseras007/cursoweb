Presentación

Introducción

En esta actividad vas a practicar la transferencia de archivos mediante clientes FTP, usando servidores públicos fiables y actualizados para garantizar la accesibilidad.

Trabajarás con FileZilla, un cliente FTP gráfico, y también con la consola para familiarizarte con el modo texto.

Más allá de la ejecución, deberás analizar y explicar los procesos, comandos y posibles problemas para afianzar tu comprensión.

Instrucciones previas

Antes de comenzar, sigue estos pasos de preparación:

  1. Accede a filezilla-project.org y descarga la versión para tu SO.
  2. Instala y ejecuta FileZilla en tu equipo.
  3. Conecta al servidor público de Tele2 para pruebas.
Dirección: ftp.speedtest.tele2.net
Puerto: 21
Usuario: anonymous
Contraseña: (vacío o correo electrónico)

Parte 1

Cliente FTP Gráfico · FileZilla

a)
Describe detalladamente cómo configuraste la conexión rápida en FileZilla para conectarte al servidor. ¿Qué opciones elegiste y por qué?

Para establecer una conexión rápida en FileZilla es necesario utilizar la barra denominada "Conexión rápida", situada en la parte superior de la ventana principal del programa. Esta opción permite conectarse a un servidor FTP sin necesidad de guardar previamente la configuración en el Gestor de Sitios, siendo especialmente útil para conexiones ocasionales o pruebas de acceso.

El primer campo que debe completarse es el Servidor (Host), donde se introduce el nombre del dominio o la dirección IP del servidor FTP. A continuación, en el campo Nombre de usuario, se escribe la cuenta proporcionada por el administrador. En el campo Contraseña se introduce la clave correspondiente, mientras que el campo Puerto puede dejarse vacío para utilizar el puerto predeterminado 21.

Una vez introducidos estos datos, se pulsa el botón "Conexión rápida" para que FileZilla establezca la comunicación. Durante el proceso, el programa realiza la autenticación del usuario y, si las credenciales son correctas, muestra el contenido del servidor remoto en el panel derecho de la interfaz.

Aunque la conexión rápida resulta sencilla y eficaz, presenta algunas limitaciones: no permite configurar opciones avanzadas como el tipo de protocolo (FTP, FTPS o SFTP), el modo de cifrado, el modo de transferencia (activo o pasivo) o claves de autenticación. Por este motivo, para conexiones habituales o más complejas es recomendable utilizar el Gestor de Sitios.

b)
¿Qué mensajes de bienvenida o información inicial muestra FileZilla al establecer la conexión? Explica el significado de los mensajes principales.

Al establecer una conexión con un servidor FTP, FileZilla muestra en la ventana de registro de mensajes una serie de respuestas enviadas por el cliente y el servidor. Cada línea refleja una etapa del proceso de comunicación.

Código Mensaje Significado
220 Welcome to FTP Server El servidor está disponible y preparado para aceptar conexiones.
331 Password required El nombre de usuario es válido y se solicita la contraseña.
230 Logged on Autenticación correcta. El usuario tiene acceso al servidor.
257 "/upload" is your current directory Respuesta al comando PWD; indica el directorio de trabajo actual.
226 Directory listing successful Listado de directorio completado correctamente.
c)
Navega por el servidor remoto y describe la estructura general de directorios y tipos de archivos que encuentras. ¿Qué utilidad pueden tener en un entorno real?

Cuando se accede a un servidor remoto mediante FTP, la estructura de directorios depende de la finalidad del servidor y de los permisos asignados al usuario. En los servidores web es habitual encontrar una organización jerárquica como la siguiente:

Normalmente existe un directorio principal como public_html, htdocs o www que contiene todos los archivos públicos accesibles desde Internet. Dentro de este directorio suelen existir subcarpetas organizadas por tipo de contenido: images/, css/, js/, uploads/...

En el servidor de pruebas Tele2 se encuentran principalmente archivos comprimidos de distintos tamaños (1KB.zip, 1MB.zip, 100MB.zip) destinados a realizar pruebas de velocidad de descarga y comprobar el rendimiento de la conexión.

En un entorno profesional, cada archivo cumple una función esencial: los archivos HTML, CSS y JavaScript permiten construir la interfaz de usuario; los archivos PHP gestionan la lógica de negocio; y los archivos de configuración como .htaccess y robots.txt garantizan el correcto funcionamiento, la seguridad y el posicionamiento del sitio.

d)
Elige un archivo disponible en el servidor y explica cómo lo transferiste. ¿Qué indicadores te confirmó FileZilla durante la transferencia?

La transferencia de un archivo mediante FileZilla se realiza estableciendo previamente una conexión con el servidor FTP y seleccionando el archivo que se desea descargar. Para subir un archivo al servidor, el usuario navega por el panel izquierdo (archivos locales) y localiza la carpeta de destino en el panel derecho (servidor remoto).

La transferencia puede iniciarse arrastrando el archivo entre paneles o haciendo clic con el botón derecho y seleccionando "Subir" o "Descargar".

Durante el proceso, FileZilla proporciona varios indicadores: en la parte inferior aparece la cola de transferencia mostrando nombre del archivo, tamaño, velocidad de transferencia, porcentaje completado y tiempo estimado. Además, en el registro de mensajes aparecen las respuestas del servidor, incluyendo el código 226 al finalizar correctamente.

Finalmente, el archivo desaparece de la cola activa y pasa al apartado "Transferencias satisfactorias", confirmando que el proceso ha concluido sin errores.

e)
Explica cómo se puede configurar una conexión guardada en FileZilla, indicando qué datos son imprescindibles para conectar correctamente en sesiones futuras.

Una conexión guardada en FileZilla se configura mediante el Gestor de Sitios, accesible desde Archivo → Gestor de Sitios o pulsando el primer icono de la barra de herramientas. A continuación se selecciona Nuevo sitio y se asigna un nombre descriptivo.

Los datos imprescindibles para que la conexión funcione correctamente son:

Servidor (Host):nombre de dominio o IP del servidor FTP
Protocolo:FTP, SFTP o FTPS
Puerto:21 (FTP), 22 (SFTP), 990 (FTPS)
Tipo de acceso:Normal / Anónimo / Interactivo
Nombre de usuario:cuenta autorizada
Contraseña:clave asociada al usuario

Una vez guardada la configuración, bastará con abrir el Gestor de Sitios, seleccionar el servidor almacenado y pulsar Conectar.

a)
Explica los pasos que seguiste para crear esta conexión guardada en FileZilla.

Para crear la conexión guardada se accede al menú Archivo → Gestor de Sitios. Una vez abierto, se hace clic en Nuevo sitio y se asigna el nombre ConexionFutura.

A continuación, se introducen todos los datos: servidor ftp.dlptest.com, protocolo FTP, puerto 21, tipo de acceso Normal, usuario dlpuser y contraseña. Se puede configurar opcionalmente el directorio remoto inicial, el modo de transferencia (activo/pasivo) o el límite de conexiones simultáneas.

Una vez completada la configuración, se pulsa Conectar para verificar que todos los datos son correctos. Si la conexión se establece satisfactoriamente, FileZilla guardará automáticamente la configuración, permitiendo reutilizarla sin volver a introducir los datos.

b)
Durante la conexión, ¿qué mensajes o avisos relevantes se muestran en el registro de FileZilla? Interpreta su significado.

Durante una conexión FTP, FileZilla muestra en la ventana de Registro de mensajes todas las operaciones que realiza el cliente y las respuestas enviadas por el servidor. Su interpretación resulta fundamental para el diagnóstico y la administración.

Al iniciar la conexión aparecen mensajes de resolución de dirección y conexión. El servidor responde con el 220 confirmando disponibilidad. Tras enviar usuario (USER) y contraseña (PASS), el servidor responde con 331 y finalmente con 230 Logged on.

Durante la sesión pueden aparecer otros mensajes habituales: PWD para conocer el directorio actual (257), TYPE I para establecer modo binario y PASV para activar el modo pasivo.

Uso de FTP mediante Consola

ftp ftp.speedtest.tele2.net
a)
¿Qué mensajes aparecen durante la conexión? Explica qué significan los mensajes relacionados con el acceso anónimo.

Al conectar con ftp ftp.speedtest.tele2.net, el cliente FTP muestra una serie de mensajes que indican el estado de la conexión.

El código 220 confirma que el servidor está disponible. Se utiliza el usuario anonymous para acceder como invitado. El servidor responde con 331, indicando que se necesita contraseña (en el acceso anónimo suele ser un correo o simplemente Enter). Finalmente, el código 230 Login successful confirma la autenticación correcta.

b)
Una vez conectado, indica el comando para listar los archivos y carpetas. ¿Qué resultado obtienes y cómo interpretas la información mostrada?

Para visualizar el contenido del servidor se utilizan los comandos ls o dir, que muestran el listado de archivos y directorios disponibles.

La información presentada incluye el tipo de elemento (archivo o carpeta), los permisos de acceso, el tamaño y el nombre de cada archivo. En el servidor de Tele2 se encuentran archivos comprimidos de distintos tamaños como 1KB.zip, 1MB.zip o 100MB.zip, destinados a pruebas de velocidad de descarga.

c)
Explica cómo descargarías un archivo llamado "1KB.zip" desde el servidor y qué pasos seguirías para verificar que la transferencia fue exitosa.
get 1KB.zip

La descarga se realiza mediante el comando get 1KB.zip, que copia el archivo desde el servidor al equipo local. Al finalizar, el servidor responde con 226 Transfer complete.

Para comprobar que la descarga ha sido satisfactoria se recomienda: verificar que el archivo aparece en el directorio local, confirmar que su tamaño coincide con el original y asegurarse de que puede abrirse sin errores.

d)
Describe el comando que usarías para subir un archivo local llamado "miweb.html" al servidor si tuvieras permisos de escritura.
put miweb.html

Si el usuario dispusiera de permisos de escritura, la subida del archivo se realizaría mediante el comando put miweb.html. Este comando transfiere el archivo desde el equipo local al servidor remoto.

No obstante, el servidor público de Tele2 está destinado exclusivamente a pruebas de descarga, por lo que normalmente no permite la carga de archivos por parte de los usuarios.

e)
Finalmente, indica cómo desconectarte del servidor FTP.
bye # o también: quit / exit

Para finalizar la sesión FTP de forma segura se utilizan los comandos bye, quit o exit. Tras ejecutar cualquiera de ellos, el servidor responde normalmente con el código 221 Goodbye, que confirma que la conexión se ha cerrado correctamente.

Parte 4

Análisis y Reflexión

1.
¿Cuáles son las ventajas y limitaciones del uso de FTP para la transferencia de archivos en comparación con otros protocolos o servicios actuales?

FTP continúa siendo ampliamente utilizado para la transferencia de archivos gracias a su sencillez, rapidez y gran compatibilidad con diferentes sistemas operativos y servidores. Permite gestionar archivos de forma eficiente, facilitando tareas como la carga, descarga, modificación o eliminación de contenido remoto, siendo especialmente útil para la administración de servidores web.

Su principal limitación es la falta de seguridad en su versión tradicional, ya que tanto las credenciales de acceso como los datos se transmiten sin cifrado. Además, su configuración puede resultar más compleja en redes protegidas por cortafuegos y carece de funciones habituales en las soluciones actuales como sincronización automática, control de versiones o colaboración en tiempo real.

En comparación con protocolos modernos como SFTP o FTPS, FTP ofrece una implementación más sencilla, pero con un nivel de seguridad considerablemente inferior. Frente a servicios en la nube como Google Drive o Dropbox, presenta menos funcionalidades para el trabajo colaborativo, aunque sigue siendo eficiente para entornos técnicos y servidores dedicados.

2.
Analiza el papel que tiene la seguridad en las conexiones FTP. ¿Qué riesgos existen y qué medidas se pueden tomar para mitigarlos?

La seguridad constituye uno de los aspectos más críticos en las conexiones FTP, ya que el protocolo fue diseñado en una época en la que las amenazas informáticas eran mucho menores. FTP transmite tanto las credenciales como los datos en texto plano, lo que significa que pueden ser interceptados por un atacante en redes inseguras.

Entre los principales riesgos se encuentran: interceptación de credenciales mediante sniffing, acceso no autorizado al servidor, modificación o robo de archivos durante la transferencia, y ataques de fuerza bruta para descubrir contraseñas.

Para reducir estos riesgos es recomendable:

  • Sustituir FTP tradicional por SFTP o FTPS, que incorporan cifrado.
  • Utilizar contraseñas robustas y autenticación de dos factores.
  • Limitar los permisos de acceso según el principio de mínimo privilegio.
  • Restringir el acceso mediante cortafuegos o listas de IP autorizadas.
  • Mantener el servidor actualizado y realizar copias de seguridad periódicas.
3.
En caso de que una transferencia falle a mitad del proceso, ¿qué procedimientos seguirías para detectar y corregir el problema?

Cuando una transferencia de archivos falla a mitad del proceso, es fundamental seguir un procedimiento sistemático que permita identificar la causa del problema y restablecer la comunicación de forma segura.

El primer paso consiste en comprobar el estado de la conexión de red, verificando que tanto el equipo cliente como el servidor mantienen conectividad. A continuación, es conveniente revisar los mensajes de error del cliente FTP y los registros del servidor.

Una vez identificado el problema, debe comprobarse que las credenciales son correctas, que el usuario dispone de permisos necesarios, que existe espacio de almacenamiento suficiente y que los cortafuegos no bloquean los puertos FTP.

Si el fallo está relacionado con una interrupción temporal, muchos clientes FTP permiten reanudar automáticamente la transferencia desde el punto de interrupción. Tras finalizar, es recomendable verificar la integridad del archivo mediante comparación de tamaño o funciones hash como MD5 o SHA-256.
